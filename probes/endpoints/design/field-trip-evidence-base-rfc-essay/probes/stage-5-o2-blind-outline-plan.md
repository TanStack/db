## Frozen public specimen

**Title:** TanStack Trust: A Base for Domain-Owned Software Guarantees

**Subtitle:** Separating domain meaning, reusable evidence mechanics, and
consumer policy

**Description:** TanStack Trust is a proposed base layer for building evidence
systems inside specific software domains. Domain packages own what their
guarantees mean and which checks have authority; the base maintains inspectable
support, contradiction, freshness, and repair records; consumers decide what
that state permits. This RFC defines those handoffs, shows the bounded Endpoints
vertical, and identifies what remains unimplemented or undecided.

**Section headings:**

1. Coding is cheap; justified reliance is not
2. The authority map: domain, base, workflow, interface, consumer
3. The domain package owns the promise
4. The base owns evidence mechanics, not domain truth
5. Workflows carry maintenance obligations across the handoff
6. Interfaces expose one service unevenly
7. Consumer policy owns permission and fallback
8. Endpoints: one bounded reconstruction of the handoffs
9. Borrowed mechanisms, breakpoints, and the decision register

## Frozen prompt family

All probes receive the complete public specimen and the same output contract.
They do not see the source track, sibling outputs, desired novelty, or overlay
labels.

- **BC-01, canonical:** “Map the argument and product you expect this RFC to
  contain from the public elements alone.”
- **BC-02, reordered:** “Using only these public elements, reconstruct what each
  owner and section is likely to establish, then identify the overall product
  claim.”
- **BC-03, neutral:** “Describe the most likely substantive RFC behind these
  public elements, including mechanisms, limits, omissions, and conclusion.”

Every probe returns: product shape; owner map; mechanism sequence; implementation
status; expected borrowed mechanisms; likely omissions; likely conclusion; and
the exact public phrase supporting each inference. It does not judge quality,
novelty, truth, or public popularity.

## Controls and risk

Three fresh sibling-hidden contexts receive one prompt variant each. Recurrence
is reported only as an exact count across these three correlated model samples.
The source map remains hidden until all outputs are fixed. No adaptive sample
will be added before the first overlay.

Shared model lineage, the highly explicit description, and the architecture-like
headings may make the ownership split recur more strongly than it would from the
title alone. This checkpoint cannot estimate public opinion or validate the RFC.
