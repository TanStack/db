# Evidence — TanStack Trust API Design Grammar v5

## Evidence classes

v5 keeps four classes separate:

1. **User-required product behavior:** the Trust/Endpoints relationship,
   linter-style extensibility, the six workflows, and the fresh-agent test.
2. **Home-system design evidence:** the RFC, previous grammar, evaluated audit
   ledger, Oracle Guide, and bounded prototype.
3. **Donor transfer:** Protocols Institute/stigmergy mechanisms, distant donor
   systems, TypeSafe's typed model result algebra, and ESLint ecosystem
   mechanisms. These are mapped proposals, not independent proof of Trust.
4. **Analyst-selected design:** the exact primitives, names, layering, policy
   algebra, task-oriented MCP surface, and unresolved-boundary placement.

User agreement with a proposal is product-direction evidence, not external
validation. Agent simulations are usability observations, not correctness
proof.

## Claims deliberately not made

- v5 is not implemented by the existing Endpoints prototype.
- The six workflow reconstructions are not passing acceptance tests.
- The selected model has not been proved minimal or formally complete.
- The ESLint transfer does not validate Trust's evidence or authority model.
- An authority-provider interface does not supply authentication by itself.
- Inert manifest discovery does not make executable third-party code safe.
- Typed probability schemas do not establish calibration or semantic truth.
- A cache explanation does not establish applicability.
- Agent success in simulation will not establish runtime correctness.
- Endpoints does not demonstrate suitability for another TanStack domain.

## Testable predictions

The condensed packet should let fresh agents complete the six workflows without
inventing a second status model, treating work as proof, using severity as
activation, or treating an override as evidence. If agents repeatedly invent
the same missing operation, DTO field, authority rule, or lifecycle transition,
that is evidence that the v5 public design is incomplete or poorly exposed.

The packet may itself cause agents to mirror its vocabulary. The test therefore
records concrete code and state traces, not only positive/negative opinions.
