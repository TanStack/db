# Evaluation of `raw-adversarial-audit.md`

Evaluation target: frozen v4 design grammar plus the cited evidence-base prototype at starting and ending HEAD `4ad19815b44be533ac10f90b62aca4377f5138d2`. The v4 package is untracked, so the evaluated bytes are identified by these SHA-256 values: `PRESERVATION.md` `288c0e45…acff`, `MODEL.md` `5d193add…f08`, `EVIDENCE.md` `82c68aa7…5d6e`, `PROCESS.md` `f38c7902…0d0`, `BRIEF.md` `c5ddeaaa…e257`, `sources.json` `347180c6…9dc`, `frozen-analysis.json` `b9f61e95…e473`, and raw review `b977cdcc…10da`.

The original claims and proposed repairs remain losslessly indexed in `evaluation-ledger.md`. This file adds the independent technical verdict, evidence, final-disposition recommendation, durable destination, and severity correction for every A item without editing the candidate or central ledger.

## Reviewer assessment

The reviewer is technically strong and unusually broad. The best findings identify real missing authority, transaction, identity, clock, replay, override, cursor, and provenance contracts. The runtime allegations around cross-producer replay, selective batches, failed-reach mutation, arbitrary LSP dispatch, and multi-writer storage all reach the stated path; independent probes confirmed the underlying behavior. The source audit also correctly catches the untracked freeze and incomplete manifest closure.

Accuracy is weakened by a recurring category error. The RFC and v4 evidence repeatedly label the new grammar as a **proposed contract**, label the current prototype as bounded, and enumerate absent APIs. A-54 through A-58 and A-67 through A-73 often treat conceptual reconstruction cases or future-tense brief examples as claims that the prototype already implements them. That turns useful acceptance tests into false implementation refutations. A-44, A-45, and A-50 similarly overlook explicit “analyst-inferred” or “transfer-boundary” labels. Sixty-one of 83 items are rated High, so prioritization does not distinguish runtime corruption from traceability debt, acknowledged absence, or analytical-control weakness. Many items also repeat earlier ledger claims without cross-referencing them.

Proposed fixes are generally directionally good, especially staged commit, fencing, request identity, authority scope, deterministic identity, and snapshot-bound preconditions. Some recommendations prescribe implementation as the only way to validate a design artifact, or expand a deliberately bounded prototype without first resolving its stated design choices.

**Hire recommendation: yes, for an adversarial architecture/security review role, with an explicit calibration requirement.** The reviewer finds high-value fractures and supplies good hostile test ideas. They should not be the sole final adjudicator until they consistently distinguish proposed design from current behavior, preserve prior canonical findings, and reserve High severity for materially different urgency classes.

## Independent RED probes

The temporary probe `/tmp/evaluate-adversarial-red-probes.mjs` exercised public methods and the actual adapter/service paths without changing the candidate:

- **A-04 / A-22 / A-36 / A-71:** observation 1 failed under producer `probe/original-producer@1`; observation 2 passed the identical claim/case under unrelated producer `probe/unrelated-producer@9`; `resolve(1, 2)` succeeded and recorded `resolutions: [2]`. `kernel.ts:519-538` checks freshness, applicability, claim, and case, but not producer/check identity or a repair link.
- **A-13:** a callback returned `reached: true` without invoking the declared production seam (`actualProductionInvocations: 0`); one passing observation committed. `runCheck()` trusts `execution.reached` at `kernel.ts:449-456`.
- **A-15 / A-35:** a contract declared a two-case domain and that it observes both cases, but the callback returned one favorable finding; one pass committed. There is no expected-case manifest/cardinality in `CheckContract` or `runCheck()`.
- **A-17 / A-69:** before failed reach, `nextRun=1`, dependencies `[]`, observations `0`; after `CheckDidNotReachProductionPathError`, `nextRun=2`, dependency `probe/source@revision 1` remained, observations stayed `0`. The mutation occurs at `kernel.ts:445-448` before the reach check.
- **A-19 / A-53:** a supported observation remained `supported` after an intentionally unreported external source change. This reaches the actual applicability path; `updateDependencies()` cannot invalidate an omitted dependency, as the RFC itself admits.
- **A-20:** submitting the exact same service request twice committed two observations; the request had no request-ID field.
- **A-26:** with both an open counterexample and a proposed unregistered route, `assess()` returned `contradicted`, one counterexample reason, `routes: []`, and `gaps: []`. The early return is at `kernel.ts:583-602`.
- **A-37:** `workspace/executeCommand` with `evidence.request` forwarded a mutating `context` operation without any principal/capability input. The real forwarding path is `lsp-server.mjs:114-120` and the real mutation is `service.mjs:91-96`.
- **A-54:** the real diagnostic projection mapped `contradicted` to LSP severity 1 and `unresolved` to severity 2, with those status strings as codes (`lsp-server.mjs:13-26`). This confirms current adapter behavior, not a defect in the proposed UC03 policy model.
- **A-69:** two real CLI processes concurrently executed `run-endpoints` against the same initialized store. Final observation counts were `[1,1,1,1,1,1,1,1,2,2,1,2,1,2,1,1,1,1,1,2]`: 15/20 attempts lost one write and 5/20 happened to serialize. This confirms the race in `service.mjs:53-56,99-107` plus `storage.mjs:55-66`, but does **not** independently reproduce the review's exact “20/20” frequency.

The surrounding baseline remained green: `npm test` passed 21/21, all eight fault controls were detected, and TypeScript checking passed. Those results do not close any RED above because the current suite does not assert those properties.
