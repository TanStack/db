## Verification and limits

[PROBE-RESULTS.json](PROBE-RESULTS.json) records the exact commands, output and exit status. Six retained probe scripts pass on Node 24.5.0 because they assert the **current defect or limitation**, not because the implementation was repaired. All seven existing evidence-helper tests also pass. That contrast identifies missing test dimensions rather than a regression in the helper controls already present.

- **OG-01:** [counter probe](probes/og01.mjs) executes the exact current compiled-runner pruning assertion through its operation increment. A mismatch prevents the counter from advancing; a matching read count advances it. Together with the recorded source hash, 71 completed operations provide bounded reach evidence for that mandatory assertion. Similar later checkpoints follow the driver's pending/retry assertions. The absence of a dedicated label is real, but it does not erase those witnesses. Keep optional branch-level reporting rather than requiring every assertion to use one helper.
- **OG-03:** [namespace probe](probes/og03.mjs) exercises the real shared finalizer. An additional **real SQL-effect runner** replay selected `needless-index-fallback` with `index: none`: it executed one write and one envelope, reported one fault event, and exited 0 with `ok: true`. The conditional fault never applied. [Input](probes/og03-replay.json), [runner report](probes/og03-runner-report.json). This proves a control-reporting flaw; the ordinary data assertions correctly passed for that unaffected domain. Survival/equivalence and application/reach must remain distinct.
- **OG-05/06:** [identity probe](probes/og05.mjs) uses the real Evidence replay path. An ID difference and a text difference at collection 0, row 0 receive `same-violation`. [dependency probe](probes/og06.mjs) extracts the exact fast-check callback from the current runner and uses the actual Evidence helper. Its later history replaces the reduced failure after an earlier different law was swallowed. A local outer-wrapper control stops at that first mismatch. The latter is a candidate repair control, not a committed fix or a full PG campaign.
- **OG-07:** [failure-capture probe](probes/og07.mjs) executes the actual compiled-browser top-level control flow with stubbed I/O delivering a wrong row. The report saves error text but has zero captured cases, `unclassified-failure`, and no replay packet. It also executes the exact loading catch/finalizer with a structured row failure and proves that structure is dropped. These test the runner boundary; they do not claim a new real-browser failure.
- **OG-02/04/09:** [boundary probes](probes/more.mjs) extract the actual route/checkpoint/response-handler code. A deferred fulfillment remains blocked through the real 30 ms wait while the pending checkpoint passes. A drained wrong publication loses its raw changes/index in the saved packet. A secondary script-response error is swallowed into a local array, while the actual loading handler produces Node's `unhandledRejection` event before its promise is collected. The resulting `PromiseRejectionHandledWarning` is expected evidence from this controlled probe, not a clean production campaign. I/O is controlled at the relevant seam; this does not establish how often these schedules occur in Chrome.
- **OG-08/10:** The same script changes a disposable copied reference file and observes unchanged real Evidence provenance. It samples 1,000 values from the actual SQL-effect step arbitrary and checks the unconditional preload before all steps. The arbitrary contains only kind/value/optimistic recipient; no generated command can create the claimed cold retained state. This is a scoped generator/path gap, not evidence that focused cold-baseline tests elsewhere are absent.

The first drafts of two verification scripts had local setup mistakes (a reserved function-argument name and a source matcher selecting a loop variable). They were corrected before evidence was credited. The retained receipts contain the final successful verification. No setup exception counted as semantic rejection.

The five previous final campaign receipts still match their 15 recorded source hashes and remain valid for their tested scope: 71 + 149 + 4 + 11 + 20 = 255 operations. They were not rerun or upgraded to evidence about the new failure paths. Directly executable reference/renderer identities omitted by those reports remain OG-08. The new kernel remains separate from the existing compiler integration; this audit does not change that status.

## Suggested repair order

1. **Preserve failures end to end:** OG-06 outer scenario, OG-05 law-specific identity, OG-04 observed trace, OG-07 fixed-runner capture, and OG-09 async diagnostics. Test each real caller boundary, not only a correctly assembled helper example.
2. **Make controls attributable:** OG-03 covers every existing mutant entry point, including conditional non-application and collateral failures. OG-08 records the actual reference, renderer and generated/mutated executable. Keep ordinary oracle correctness separate from the sensitivity-control verdict.
3. **Add the missing histories:** OG-02 needs a client receipt-processing witness; `route.fulfill()` completion alone still need not prove application processing. OG-10 needs a retained cold collection driven through the actual registry/client mutation path, alongside an unaffected warm peer.

Do not implement failure identity by freezing every numerical row index or concrete value. Shrinking may legitimately remove a preceding row or simplify data. Each law needs a stable semantic distinction (for example membership, order, projected field, operation family) and a predicate that rejects drift into an unrelated accusation. Likewise, fixed experiments need reproducible case/encoding/operation information, not forced randomization.

## Reviewer assessment

**Use this auditor again for bounded static oracle reviews.** Nine of ten reported losses are supported within the scope it stated; the tenth accurately identifies missing labels but underweights existing control-flow witnesses. It separates test flaws from product bugs, preserves explicit deferrals, and gives precise source references without claiming experiments it did not run. Its analysis is deep and useful. The main correction is to avoid treating one preferred instrumentation format as the only valid form of reach evidence.

It supplied no severity ranking or fixes because the selected loss-audit instrument forbids those judgments. That is proper scope discipline, not a review omission. Priorities and candidate repairs above belong to this evaluation.
