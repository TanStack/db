# TanStack Trust: In Search of Hardness — Preservation Contract

Confirmed for exact-equivalence Design Grammar run 66. The architecture source
is frozen through Field Log event 1102; confirmation is event 1106.

1. **H1 — Lifecycle-wide search.** Trust finds mechanisms across the software
   development lifecycle that can independently constrain, reject, measure or
   falsify agent-produced work, then exposes them as guidance, obligations and
   repair paths.
2. **H2 — Lifecycle subject graph.** Subjects and relationships span product
   requirements and user journeys through source, APIs, database operations,
   builds and deployments to production behavior and SLOs. Code is one
   projection, not the whole substrate.
3. **H3 — Native hardness.** A domain protocol states what its substrate does,
   enforces or refuses and exposes facts, laws, capabilities, impossibilities
   and explicit unknowns within that boundary.
4. **H4 — Derived hardness.** A higher-level protocol may establish additional
   guarantees from lower-level facts plus its own semantics while retaining the
   derivation and authority chain.
5. **H5 — Oracle hardness.** A package may provide a reference model,
   generators, production-path runner, comparator, reach witness, shrinking and
   replay as a bounded oracle evidence method.
6. **H6 — Statistical honesty.** Property-based testing provides randomized
   falsification and bounded coverage. Statistical confidence additionally
   requires an explicit sampling distribution, independence assumptions,
   stopping rule, calibration and confidence interpretation.
7. **H7 — Required hardness.** Packages and projects may introduce requirements
   such as latency, security or product constraints. Intent becomes hard only
   through qualifying evidence, maintained applicability and enforcement or
   refusal.
8. **H8 — Authority separation.** Definitions, facts, derivations, evidence
   methods and records, adequacy, applicability, requirements, conditions, work,
   policy and authority remain distinct. Shape, task completion, PR state,
   caching and agent assertion do not transfer authority.
9. **H9 — Cross-owner composition.** PostgreSQL can supply reusable subjects and
   native facts, Endpoints can add domain semantics, and providers such as Neon
   can add bounded runtime evidence without copying subjects or redefining
   foreign truth.
10. **H10 — Agent legibility and proposal.** Agents can discover requirements,
    explanations, evidence gaps and todos; gather authorized evidence; and
    propose new hardness sources or proof routes without admitting themselves.
11. **H11 — One operation model.** Package/project configuration, source-local
    declarations, relationships, histories and typed operations project one
    meaning through TypeScript, LSP, MCP, CLI and Devtools. Local declarations
    cannot weaken higher-authority requirements.
12. **H12 — Honest range.** Endpoints and its finite evidence kernel are the only
    executable implementation evidence. Lifecycle-wide protocols, standalone
    PostgreSQL adapters, Neon execution, product-requirement integration and
    cross-domain range remain proposed or untested.
