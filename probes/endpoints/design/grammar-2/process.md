# Process and projection support

Second exploratory Design Grammar, analysis version 1. This is the audit trace; the human brief is drafted only after this file, Model, and Evidence are frozen.

## Scope and execution

1. **S1 — Source/target freeze:** `source-freeze.json` pins the current Endpoints runtime/compiler, source trace, prior analytical boundaries, actual oracle receipt, and completed sharing experiment. The extraction target is bounded analysis and update planning in this system, not a synthesis of multiple vendor architectures.
2. **S2 — Preservation:** P1–P12 were materialized in `preservation.md` before Model. Mode is exploratory with provisional analyst-derived conditions alongside explicit user constraints. The prior run is not overwritten and exact equivalence is not claimed.
3. **S3 — Extraction:** M1–M5/L1–L5 retain state, intent, observation and demand distinctions. C1–C9/R1–R12 introduce explicit limits on inferred transformations. Observation, required behavior and proposed structure are labeled separately.
4. **S4 — Reconstruction/ablation:** RC1–RC3, A1–A6 and the rule-removal table below test coverage and trim redundant units. These are analytical controls, not executable mutations of the framework.
5. **S5 — Range/exclusion:** RG1 remains untested independently. NC1–NC6 retain measured and analytical negatives with their different status. No new instrument or source search was run.
6. **S6 — Generation:** Two unranked ownership forms, F1/F2, combine sourced relations and explicit added structure. SQL/encoding choices remain orthogonal. Cosmetic or universal-optimization forms are excluded rather than used to fill a quota.
7. **S7 — Freeze/projection:** Hash Model, Evidence, Process and Preservation before creating Brief. B1–B8 below are its allowed claim support. Drafting may compress those claims; any new claim requires a new analysis version before projection.

## Observation/inference ledger

- **O1:** Current runtime binds bare collections and synchronous actions, tracks direct local mutations, then awaits RPC and target refetch (E1).
- **O2:** Query extractor admits a narrow grammar with assumptions; binder rejection and emitted order/identity differ from generalized evidence or schema guarantees (E2).
- **O3:** Saved receipt fails at the optimistic checkpoint for the second result; later code paths are inspected source, not observed continuation (E3/E5).
- **O4:** Sharing experiment has executed narrow correctness/byte/time results; its measurements cannot be treated as general SQL or framework performance (E6).
- **UO1:** User selects bounded optimization and inline full-result fallback. This is an authority/target fact, not observed software behavior (E8).
- **I1:** Evidence is attached to the particular transformation it supports; execution admission and optimization admission can differ (C1/C9).
- **I2:** Read candidates and tentative settlement participants must be represented separately when actual effects diverge from predictions (R4/NC5).
- **I3:** Safety and cost are separate admissions; selection overhead counts, and no cost threshold is inferred (C8).
- **I4:** F1/F2 require added discovery, interpretation, coverage and publication contracts; neither is already implemented or certified modular.

## Source reconstruction

**RC1 steps:**

1. Two different declaration identities create two Qs and query-owned Hs under one client/scope. Their consumers produce D requirements. Available L5 evidence is narrow identity/order, not general semantic equivalence.
2. T captures an insert into the first H through L2. No rule in the current source adds an edge to the second H. Its missing optimistic row is therefore reconstructed, not explained away by desired coherence requirements.
3. The saved receipt stops at that divergence. For the inspected successful source path, mutation O is followed by full-query O for direct targets. L3 uses that ordering to settle T; no general cross-query baseline or atomicity is claimed.
4. Failed query extraction currently prevents compilation. The target's conservative-execution form is not substituted into the source reconstruction.
5. Source errors and retry configuration are retained without treating read failure after acceptance as proof of write rejection.

**RC2 steps:**

1. Fixed query instances and unchanged server data define complete result observations for three Qs.
2. Independent evaluation and shared-join evaluation produce equivalent result arrays in the measured fixture. M4 construction changes under C6 while Q identity/order remain fixed.
3. Shared encoding factors repeated projected rows into a pool and ordered references. M4 representation changes under C7; the pool is not promoted to shared persistent H.
4. Changed bucket parameters reduce A6 overlap, increasing encoded bytes despite preserved results. C8 represents that loss without changing semantic admissibility.

**RC3:** R5 can represent the user's inline-full baseline, but U2/U3/U4 explicitly retain missing implementation contracts. Representability is not completion.

**A4 — Operation pruning:** C2–C7 are transformation families, not extra semantic units. They remain distinct because removing each loses a distinct permitted move: skip an unchanged query, derive optimism, avoid full evaluation, encode a difference after evaluation, share SQL work, or share response rows. C1/C8/C9 qualify those moves rather than adding more storage layers.

**A5 — Form pruning:** Prior equivalent-query coalescing is a restricted specialization of F1. A third “server delta architecture” merely binds an orthogonal C4/C5 choice; merge it into delivery alternatives. A third “always shared” form conflicts with P12; exclude it. This leaves two ownership transformations with different active dependencies.

**A6 — Candidate-unit compression:** A general planner, a capability object, a shared batch, and a row pool can all be removed as named primitives without losing RC1/RC2: rules/evidence annotations and O construction/encoding retain their function. Demote them. This shorter grammar is a modeling heuristic, not a claim of unique or objectively minimal architecture.

## Generation and interface check

F1 augments transaction-to-result relations while retaining separate ownership. F2 factors supporting state and changes derivation/ownership relations. Each names added structures, preservation obligations, costs, exclusions, and U1–U6. Both retain shared execution and encoding as independent optional paths. No threshold, priority among unresolved policies, or implementation winner is selected.

The only newly executed interface check belongs to E6's experimental result encoding. It does not cover transaction publication, arbitrary output identity, or shared support retention. Thus neither F1 nor F2 is generated through an asserted framework module substitution.
