## Bounded readings

Ground Condition separates compiler-derived support, real application oracles,
mock-dependent evidence and missing behavior. A baseline must bypass the
optimization being tested; actual write completion remains a separate premise
even when optimized and baseline paths agree.

Fracture Scan exposes three links needing rules: a passed check versus the
requirement it supports; compatibility when combining evidence; and consequence-
aware task order. It rejects the idea that all tests must be universal proofs,
and rejects unrelated external writes as an internal counterexample.

The fresh audit preserves most of v0.1 and asks for two explicit transitions:

- **H1:** a compatible unresolved counterexample must have a defined effect on
  current admission. Merely opening a task does not withdraw permission.
- **H2:** future-use containment, past exposure and repair evidence are separate.
  Disabling an optimization does not itself refresh a view it already left stale.

These are audit repair conditions, not changes secretly applied to the frozen
candidate. The sampled-evidence admission rule, remote context binding,
dependency discovery and priority defaults remain declared design choices.

The user's later authority requirement adds a distinction between agent-proposed
records and machine-derived permitted use. A reliable runner can attest what ran;
that alone cannot establish that a test observed the right law. The ultimate
acceptance rule and its dependencies remain part of the system's trusted boundary.
The follow-up distinguishes observation, interpretation and authority. Its four
probes concern direct receipt edits, authentic runs with the wrong comparison law,
self-approved control changes, and a consumer bypassing a correct denial. It
selects no enforcement infrastructure and does not require review of every test.

## Scope and validation

No evidence engine or production code was implemented; no new runtime tests
or production measurements ran. Cases are constructions; source pointers identify
prior observed code behavior and existing written requirements. This packet does
not establish incident likelihood, team trust or a formal proof of soundness.

guide words for each node/parameter, empty unreviewed fields, per-row rendering,
audit IDs and local links. That validates the record, not the design's truth.
