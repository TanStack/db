# Selective refresh: values and work

This history supplies two distinct failures. The legacy analyzer returned correct
values but refetched too much. An injected missing-effect fault produced stale
values. A separate needless-fallback fault preserved values but failed the exact
read-count law. The process cannot collapse these into one undifferentiated pass.

## Evidence process

The legacy precision failure motivated the SQL routine-effect kernel. The new
campaign recorded value and read-count comparisons separately. Named fault
controls tested both kinds of failure. A later generated stale-value case was
shrunk while retaining its original violation; reductions into the count failure
were rejected. The retained case reproduced the value mismatch with the injected
fault and passed without it.

The stronger report has conjunctive prerequisites: the value and count checks,
plus the selected fault controls. The control order can commute in the model.
The replay contrast separately requires a saved same-violation history and both
fault-enabled and normal-checker observations. A generic red exit cannot replace
those observations.

The countermodel credited value agreement alone as optimization quality. The
legacy receipt disproves that rule. The corrected grammar excludes it and also
excludes replay without a retained failure. Both recorded episode projections
replay after the correction. Removing an injected fault is a test contrast, not
a newly found production bug.

## Bounds

The measurements establish result-read behavior within the generated SQL-function
programs. They do not measure latency. This particular runner uses real registry,
JSON transport serialization and client collections in process; it is not a fresh
HTTP/browser campaign or broad PG grammar test. Its reference/value expectations
and exact read obligations have separate derivations, as documented by the source.

Automatic reporting to the future evidence system remains a requirement from R6;
saved JSON reports do not mean that integration is already implemented. Production
admission and check strictness remain outside this replay model.
