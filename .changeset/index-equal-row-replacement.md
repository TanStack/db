Keep indexes and filtered subscriptions current when a sync write replaces a row with a deep-equal one. A reference-valued field such as a `Map` could stay indexed under its old instance, so a later update left a stale entry and ordered reads could repeat one row and omit another. A subscription or live query filtered on such a field by reference now loses or gains the row when its instance is replaced, including through joins, functional filters, ordered queries, filters over a projection and pooled queries. An ordered query also takes the position of the new instance, and a `distinct` query always shows an instance some row still holds. A reader that keeps the row is still told nothing, because its value is unchanged. A subscriber that buffers a truncate replay also drops a row whose reference left its filter during the replay, and an Effect's joins follow a row whose reference a truncate replay replaced with a deep-equal instance. An Effect still reports a real update that a joined source delivers while deep-equal replacements run, and a pooled query no longer keeps discarded views alive or evaluates their filters on deep-equal writes. A real update between values that hash alike, such as a class and a plain object with the same fields, now reaches ordered queries and joins too. An ordered pooled query no longer notifies readers when deep-equal replacements leave its order unchanged. `distinct` accepts keys and payloads outside the selected identity that cannot be hashed, such as cyclic ones, and never shows an input of weight zero. A truncate replay's deep-equal replacement also reaches a filter on the new instance after `distinct`.
