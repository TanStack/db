'@tanstack/db': minor

Compare instances of value classes, classes whose instances define `toJSON()` such as the `surrealdb` SDK's `RecordId`, by their serialized value instead of by reference. `eq`, `inArray`, join conditions, `groupBy`, indexes and ordering now match a distinct instance with an equal `toJSON()` result, so filtering or joining on record IDs works in any table. Query identity follows the same relation: equal captures are one query, so `useLiveQuery` needs no `queryKey` for them, and `getStableValueHash` (and therefore a `queryKey`) accepts such instances instead of throwing `UnhashableQueryIRError`. A value class instance never equals a plain value equal to its serialization. Dates, Temporal values, binary data, Maps, Sets and RegExps (including subclasses that define `toJSON()`) keep their own rules, and plain objects, arrays and classes without `toJSON()` still compare by reference. Range predicates (`gt`, `gte`, `lt`, `lte`) order a value class by the same serialized value as `orderBy`, rather than by `valueOf()`. Range predicates over arrays now compare them element by element in the order `orderBy` gives them, whether or not they hold a value class, so `[2]` is less than `[10]` and the order is transitive; where sorting would order two plain objects or two symbols by identity, the arrays compare as equal from that element on, and a symbol sorts after a nested array as it does in `orderBy`. Replacing a value class with an instance that serializes differently counts as a row change even when its enumerable fields are unchanged. A value class's `toJSON()` is read once, the first time it is compared or hashed, so instances must not be mutated afterwards.
