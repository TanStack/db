Keep an ordered live query loading when work overlaps a bounded repair. A request that a repair superseded no longer blocks refills when it fails. The loader recovers with one full-source read and then releases the failed request. A repair that answers at once no longer waits behind the older request. A failing request no longer drops the next step of the repair, and a throwing release inside a window move no longer stops the repair. A page that changes the order during its own delivery no longer counts as current, so the repair releases the tie that it started. When a truncate replay starts a replacement repair, the replacement now releases the old repair prefix that settles later. A replay no longer counts a full-source read as complete after an explicit retry released it. A failure from before a truncate no longer drops the staged step of the next repair. A request of a replaced repair no longer continues that repair or counts as its own failure. A repair request that settles after a full-source read covered the source is now released. A retry whose release starts a truncate no longer releases the failed requests that the replay owns. A full-source request that fails after a truncate replay covered the source no longer blocks refills or forces a second full read. A repair request that fails after a replay finished its repair is recovered without an explicit retry. A release that runs the graph during the settlement of another request no longer lets two requests run at the same time. A truncate replay that covers the source now releases the failed requests that a repair superseded, so an Effect no longer holds them. When a release throws during a replay, the replay rows now publish. When a release throws after a successful ordered load, the live query no longer keeps its old rows. When an adapter's `unloadSubset` throws, the ordered loader now reports the error as an uncaught error and changes no load result. A window move whose load succeeded now moves the window and resolves. When a recovery read throws while it starts, the request that it recovers still reports its own error.
