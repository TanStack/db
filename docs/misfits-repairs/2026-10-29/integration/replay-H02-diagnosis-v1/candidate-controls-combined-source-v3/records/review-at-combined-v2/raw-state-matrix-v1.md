candidate; baseline can establish only named constituent premises. `U` means
the premise needs source/authority clarification before it is a legal-history
reach requirement. No absent candidate seam fails baseline, and no classification
authorizes an invocation or lowers a reach minimum.

## Reach accounting and interpretation

Baseline-available components should have their own exact boundary names and
their own positive observations, without claiming a future fence/task path.
The original 20 names remain the candidate inventory; do not populate a
candidate counter by translating an ordinary baseline analog into it.

For each generated normal campaign, count histories that actually reach a
declared state, once per history, with the declared minimum enforced. Report
baseline component counts, candidate counts, helper calibration results, real
host progress, and fault-comparison outcomes separately. A single aggregate
count can hide missing root, child, current-run or real-host paths.

The current payload oracle cannot judge these 20 states by phase names alone.
All submitted candidate cuts need typed validation and an explicit shared
comparison branch before their reach can support a repair claim. The plan's
calibrations must reject plausible wrong outcomes at those same cuts. A setup
exception, absent seam, resource termination, or unexecuted fault has no product
RED/GREEN or hostile-mutant credit.
