# Queued progress and completion-cut scope

This is an additive clarification. Own v1 and v2 frozen sources and records
remain immutable. It changes no law, source file, runner, budget or runtime
admission.

`existingOperation` is required only by the completion-specific `host-gap`
observation. That cut intentionally judges an existing pending public window
operation (raw state4), with an additional partial operation when supplied
(raw state5). Its required identity prevents a malformed observation from
silently skipping that promised comparison.

An active window operation is not a premise of the accepted conditional
queued-progress law, a general prerequisite for a queued continuation task,
or a universal requirement for real-helper receiving. A finite queued answer
can need host progress with no active public operation.

The original owner, eight examples, canonical conflict and no-window variants,
three-member generated family, budgets and replay runner remain preserved.
The original production driver still preloads the live query/downstream and
then calls markers.reload without calling live.setWindow. None of these
histories acquires a new setWindow requirement through the completion bridge.

The candidate completion host-gap recipes deliberately exercise both progress
and completion. They do not discharge the separate real-helper neighbor with
no active public operation. That receiving witness remains required under the
primary queued-progress owner, with the native receiving driver supplying the
actual helper path. The source packet preserves the original histories; the
new actual-helper/no-active-operation neighbor is not executed or credited.
Its receiving reach remains UNREACHED until separately admitted and measured.

Future binding must select the ordinary queued-progress driver for those
original histories and the completion driver for a completion-specific cut.
It must not require an operation identity before scheduling general graph
progress, invent an operation solely to satisfy the recorder, or mark the
no-operation neighbor reached by running the completion recipe instead.
