## What the exact packet currently does

The three live `scripts/h02-progress/candidate-controls*` sources match their
frozen V4 copies byte-for-byte. They provide a narrow scheduler replacement,
exact-graph wrapper, promise observer, one-shot public-delivery fault, receipt
recorder, and host-gap capture. Their nine ordinary tests calibrate those
helpers on fake graph objects, authored callbacks, and native promises. No
calibration invokes the real QueryClient/live-query path.

The only references to the candidate helpers are their definition and those
calibrations. `createCandidateControlReach()` has no caller. No receiving
history calls its `beginHistory`, `reach`, `assertReached`, or `counts`. All 20
product-state counts therefore remain UNREACHED. The proposed
`graph-continuation.ts` module is absent. Refusing to install its mock in
baseline is correct; adding a production stub to make baseline tests collect
would not establish a host cut.

The H02 primary owner is
`packages/query-db-collection/tests/queued-answer-progress-oracle.ts`. Its
`ProgressHistory` selects query versus synchronous controls, microtask versus
timer, two cache identities, inline include/window booleans, prior nonemptiness,
key translation, and rank scale. Its actual driver uses real QueryClient and
Query DB, finite predicate-only answers, public reload/preload, and raw
acquisition/cache/publication receipts. The two generated campaigns each request
eight families, and each family preserves strict empty/nonempty profiles.

That history has no explicit window move, retry, output hold, facade mode,
graph/status/subscriber failure, or cleanup/restart interleaving. The driver
never calls `setWindow`/`getWindow`, installs a persisting output transaction,
binds an exact graph, or uses candidate controls. Its existing public row
recorder assumes `markers` is an array.

Two additional source gaps matter:

1. The include uses `toArray()` over the same marker source that the anti-join
   rejects. Every eligible root has an empty include. This profile creates no
   Collection-valued child facade and cannot exercise facade A/B or restoration
   obligations merely by enabling a scheduler mock.
2. The current shared check recognizes initial/retained/immediate/final rows and
   reload public-change events. It has no judgment for candidate gap records,
   chosen/settled windows, operation promises, applied-receipt cuts, error
   identity/scope, or stale task effects. Passing an arbitrary new phase to it
   can do nothing. Its `ProgressReceipt` string phase/index signature does not
   make an unknown phase a checked observation.

### Bind real objects and preserve the host boundary

Keep `candidate-controls.ts` as recorder/control support. Add an ordinary
receiving driver companion and separately selected runner; do not put product
expected values into its calibration tests or import a registering `.test.ts`
file as a model.

Install the exact module replacement before dynamically importing the candidate
production path. The preferred future interface remains
`scheduleGraphContinuation(task: () => void): () => void` in internal
`query/live/graph-continuation.ts`. It is a proposed binding spelling, not a
baseline module or public token/fence API. Source review must adopt that spelling
or explicitly update the binding. Never intercept global timers.

The existing internal utility is sufficient to obtain the exact query's
builder: `live.utils[LIVE_QUERY_INTERNAL].getBuilder()`. Capture its current
sync-state and graph identity after the initial query is established, before
the controlled reload/window action. Rebind only at an explicitly modeled
restart. The graph wrapper records dispatch-associated `run()` entries; it does
not prove an accepted normal turn when D2 is already quiescent. For that cut,
also observe the exact sync-state's real `flushPendingChanges` entry/return
and current-run identity. A builder call that hits a reentry guard is not
accepted resumption. All wrappers delegate unchanged except a declared fault,
retain originals, and restore in finally.

At every public `setWindow` call, record options, call-stack return, literal
`true` versus the exact returned promise, and install its observer immediately.
Record `getWindow`, root/facade reads, callbacks, and downstream reads at the
named cut. Do not wrap or delay the operation promise to manufacture pending
state. The host-gap helper's native timer allows native microtasks to run, but
must additionally observe the selected answer's execution and actual last
relevant demand settlement. One timer turn alone proves neither. Keep the exact
continuation undispatched during that cut.

Record the trigger independently: the exact subscription's preexisting replay
hold before demand effects, the actual `DemandUpdate.changed/ready` result,
the exact builder's input revision before/after the real callback, and actual
pending D2 work. Baseline `CollectionSubscriber.setDemand` returns void, but the
existing `SubsetDemandController.setDemand` returns `DemandUpdate`; a narrowly
bound test wrapper can observe that returned value without changing it. A cache
conflict receipt or accepted acquisition Promise alone is not this conjunction.
Complete-operator stopping itself is a later candidate observation.

Keep two production-driver modes: real helper for actual-host progress, and
module-controlled helper for exact completion/failure cuts. They share law,
input programs and comparisons. A queue the test deliberately holds can never
prove that the real helper yields to the host.

Tie/refill and fallback controls need another explicit attachment. Current roots
are supplied as one five-row batch, all ranks are distinct, and the marker
provider deliberately refuses ordered/window hints. A genuine page/tie/refill
program needs a finite on-demand root provider that fulfills the exact order,
limit, cursor and leading-tie contract, or an appropriately adapted existing
ordered-lifecycle driver. Do not ignore hints or label the current full batch a
refill. Add independent tied-order facts and the contract's stable tie-breaker
to the new profile's reference calculation. Keep the existing distinct-rank
model and predicate-only provider unchanged for original profiles. The finite
five-row literal-true neighbor establishes its named initial cut, not all these

An unrecognized candidate cut must fail instrument validation, not silently
return. New judgment includes:

- Prior coherent root/facade/downstream snapshot and settled window while an
  authored required publication obligation remains pending.
- The winning requested window and independent final relation after that
  obligation and a successful whole publication tail, including inherited
  partial options and older-call joining behavior.

  one-shot releases at their own cuts.

  downstream advance while a root callback is still executing.

child facts, authored outstanding prerequisites, logical current/retired run,
and the dependency/error distinctions an observable next action needs. It does
not copy builder tokens, private queues, D2 revisions, gate classifiers, or the
receipt registry to compute expected truth. Those are reach instrumentation.
Repeated-yield tests judge public obligation continuity rather than private
completion-promise equality.

Separate success and failure histories. The current successful-answer checker
requires exit zero, no sync error and a final successful publication; a legal
failure/cleanup history must use the newly specified failure/lifecycle branch,
not skip those assertions by an environment selector or relax all outcomes.
Keep resource/setup/observation/cleanup failures distinct from product mismatch.
Preserve the original failure/checkpoint through capture and cleanup.
