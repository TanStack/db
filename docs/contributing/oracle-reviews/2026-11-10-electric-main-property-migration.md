# Electric adapter campaign registration migration

The main Electric owner now registers its eighteen generated comparisons with
`oracleProperty`. Its existing independent Maps, retry model, authored helpers,
production paths, comparison checkpoints, seeds, and generated run budgets
remain. The shared assertion adapter transports the existing comparison's
judgment; it does not compute new expected behavior. Original comparison errors
retain their causes and stacks. Setup, production, and cleanup errors propagate.

The fixed mutation matrix keeps its per-case checkpoint requirements and the
retry owner keeps its four per-history minimum-one census checks. Local Sets
and Maps record those same observations without importing the legacy campaign
API. These retained checks do not claim the stronger constructed-history reach
guarantees of a redesigned oracle.

The three former examples accepted by their arbitrary now run as native fixed
histories, once for each former campaign. The retry examples include authored
schedules outside the mapped arbitrary's shrink domain. They remain ordinary
fixed replays through the exact same declared `checkRetryHistory` helper, twice
as before. The random arbitrary is unchanged. Fixed examples stand aside during
path replay. The source-ledger calibration gains a registered property name;
its twenty-run fixed and random campaigns retain their checks and seed.

Replay manifest selectors now target each native `random seed` test. This
conversion removes one `legacyCampaigns` exception. It depends on the shared
assertion adapter already integrated with the serializer/descriptor batch.

Validation used the existing local installation, two workers at most, coverage
disabled, and type checking disabled. The complete Electric owner passed all
192 tests. `oracle-replay.test.ts` passed all 116 tests; its manifest-only check
also passed all 69 selected tests. A guarded replay of
`electric.retry-decision`, seed 42/path 0, passed one test with one matching
completed witness and 191 tests skipped. Targeted ESLint and `git diff --check`
passed.

The direct package TypeScript check found the required `law.owner` metadata
missing from the new registrations. After adding it, the check reports only
seven dependency-resolution errors in unchanged e2e imports and SQLite's
`@standard-schema/spec` import, with no diagnostics in the changed Electric
tests. The preceding serializer/descriptor metadata correction is committed
separately.

The run-budget checker reports seed 20260924 as 20 to 8 because its single seed
key conflates the unchanged twenty-sample grammar calibration with the
unchanged eight-run queued-presence campaign. Both remain in this file with
their original counts. No budget was lowered. The local dependency repair is
an ignored `query-db-collection/node_modules` link to the existing install; no
dependency manifest, lockfile, or override is part of this commit.

This is an API migration, with no production change, mutation census, new
real-provider claim, or bug-class closure. The owner's existing controlled SDK
boundary and stated limits remain. Canonical installation and type checking
run on integration.
