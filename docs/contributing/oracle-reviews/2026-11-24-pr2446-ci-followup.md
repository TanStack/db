## Synchronous source acceptance

**Law.** An idle eager source with no managed cache claim enters core during
its `commit()` call, before its durable receipt settles. A later abort cannot
revoke the accepted transaction. Ordinary writes wait behind a persisting
optimistic transaction; truncate applies at once beneath it. Authority:
README Source replay ordering and sync-present durability, the primary
`persisted-oracle.test.ts` contract, and the opening contract of
`db/tests/optimistic-history-oracle.ts`.

**Defect and gap.** The preceding authority repair awaited an async admission
helper even when no cache claim existed. That added a promise continuation
before core acceptance. CI found delayed publication, an accepted predecessor
instead rejected by a later abort, and broken queued Query/Electric writes.
The managed-claim grammar always held an authority/read turn. The older FIFO
histories parked a predecessor, so neither judged an idle `commit()` return.

**Reach.** The new `source-publication` family lives beside the primary FIFO
model. Its independent Map transformation crosses insert/update/delete/truncate
with a persisting local mutation and a post-commit abort or live signal. Ten
states each have five builders. Each builder reaches five histories per fixed
and fresh campaign on recording storage, Node SQLite and actual Chromium/OPFS.
The driver observes the actual transaction state and signal after commit.
Constructed-output validation and a missing-state control for every builder
keep those reach claims observable.

**RED.** On unchanged production the focused extended comparison fails four
Node checks across recording storage and SQLite, and two Chromium/OPFS checks,
with no type or setup failure. Earlier broad discovery also included a mistaken
call of the framework's `pass` value; that type failure supplies no RED evidence.
The corrected focused pre-edit runs establish the publication defect.

**Repair.** Await admission only when a cache claim exists. Retain the final
synchronous currentness check for every transaction. Managed claim renewal
retains both its awaited admission and its application-time currentness check.
No new recovery state is introduced.

**GREEN.** Twelve selected Node files pass 2,367 tests with two existing todos
and no type errors. After independent review strengthened prefix fidelity and
abort reach, the final publication family passes 436 Node checks and 218
Chromium/OPFS checks. The previously failing Query receiving file passes 24;
Electric's recovery and integration selections pass 529, both with no type
errors. Those receiving tests required no expectation edits.

**Mutant.** Reintroducing the unconditional await fails four selected Node
checks and two Chromium checks. Explicit transform-load markers establish that
the wrong source ran. Separate failures judge `commit return` under
`synchronous source acceptance`, and `accepted completion` under
`accepted source completion`. The latter retains an actual held mutation and
an aborted post-commit signal. It is not inferred from a no-abort failure.

Independent review also rejected two instrument gaps. Later receipt/read errors
could erase a completed prefix, and reach was derived only from the input.
The recorder now returns completed prefixes plus later execution and cleanup
diagnostics. The comparison judges the synchronous prefix and receipt before
later execution/final-state failures. A real dual-fault driver, forwarded into
Chromium, corrupts the commit observation then fails the durable observation;
the calibration must reject the original prefix under its own law. Actual
transaction/signal observations and per-builder missing-state controls replace
the unmeasured reach. The reviewer approved the final bounded repair.

The first draft also overconstrained truncate under an optimistic hold.
The existing optimistic contract explicitly makes truncate apply at once.
Correcting that independent model rule required no further production change.

**Limits.** One eager idle source turn following completed startup, one optional
local optimistic transaction, and one post-commit signal outcome. Existing FIFO
and managed-claim families retain their read/queue/recovery histories. This
family establishes no arbitrary multi-tab or mobile scheduling guarantee.

## Accepted TrailBase SDK limitation

CI reproduces the SDK's JSON exponent-integer defect on both eager campaigns.
SDK 0.14.3 calls `BigInt` on `Number.MAX_VALUE`'s valid exponent token and throws
before adapter delivery. The maintainer explicitly accepts leaving this open.
The actual SDK receiver excludes only that exact generated value through its
existing `excludesValue` boundary. All seven kinds, 600 histories per campaign,
five constructions and all controlled RecordApi values remain.

The ordinary `sdk-numeric-known-defects.test.ts` retains the exact parser
`SyntaxError`/`BigInt` signature and snapshot/SSE counterexamples through the
unchanged shared model and driver with defect inputs enabled. Three signature
tests pass. The SDK eager family separately passes all 136 units. A corrected
SDK makes those signatures fail, requiring removal of the exclusion. Setup
errors or a different shared-law failure do not satisfy the signature matcher.
This is an accepted, documented limit, not a product repair or a waiver of
other values or failures.
