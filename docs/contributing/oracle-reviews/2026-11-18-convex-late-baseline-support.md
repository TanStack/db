# Convex later baseline and reference-identical provider support

The authority refinement below supersedes the initial zero-write instrument.
Zero row writes are not a product obligation. The accepted public obligation is
that provider-confirmed rows resist later hydration and are removed by later
authoritative provider omissions. The initial run remains recorded below so
that this correction does not silently change its evidence.

This record extends the controlled [baseline neighbor instrument](2026-11-18-convex-lazy-baseline-neighbors.md)
before repairing the second Convex production candidate. It records an actual
counterexample, not repair closure. The [manifest](2026-11-18-convex-late-baseline-support-red.json)
binds the source, instrument and log hashes.

- **Law:** every coherent callback reconciles the current accepted baseline.
  A retained provider range also acquires authority for each returned key when
  its rows already equal accepted hydration seeds and no sync writes are needed.
  A later coherent omission removes that key. Authority is the glossary's
  hydration seed/source snapshot law and Convex's retained reactive cursor range
  contract. Public hydration of a previously unwritten key is legal; it does not
  need to be a source write to become part of the adapter's current baseline.
- **Reach:** `convex.lazy-late-baseline` first accepts a complete provider answer,
  publicly hydrates an absent key, then supplies a later equal, changed,
  omitting or empty exhausted answer. Each campaign constructs all four answer
  kinds and generates 12 further histories, through both SDK subscription shapes.
  `convex.lazy-support-baseline` starts with retained ranks 0, 1 and 101 while
  1000 and 1001 stay unread. It installs a new coherent provider cache with rank
  100, hydrates that exact cached object through `DbClient.applyCollectionChunk`,
  and directly verifies that every accepted row is reference-identical to its
  cached counterpart. The callback produces zero sync batches. Its next range
  contracts to ranks 0–5. Generated rank scale, ordering direction and text vary
  both histories; both campaigns construct the required state from generated
  inputs. Required reach is checked for each generated history.

  `pnpm exec vitest run tests/lazy-paging-baseline-oracle.property.test.ts --coverage.enabled false --typecheck.enabled false`.
  The result is **6 failed / 74 passed**. Four fixed/random constructed/generated

  React receiving shapes report the same semantic mismatch. Two additional

  51 neighboring units pass. The fixed campaign seed is 20261118 and the failing

- **GREEN:** pending the parent-owned production repair. TypeScript passes for
  the Convex package. Scoped formatting and lint are checked separately.
- **Mutant:** the unchanged candidate itself is the demonstrated wrong design:
  a zero-write callback forgets to retain newly acquired provider authority.
  The separate later-baseline family is intended to reject a future first-only
  baseline sampler; a source mutant run is still required before claiming that

- **Limits:** controlled immutable SDK caches, actual public DbClient hydration
  and real core. This does not establish actual Convex SDK cache identity,

  judges finite prefixes and saved suffixes on Node SQLite and Chromium/OPFS.

The no-op defect is a missing generator dimension in earlier tests: all external
baseline changes happened before the first source answer, or later callbacks
changed at least one row reference and therefore wrote a batch. A no-write
callback can still change provider support, a distinction the earlier grammar
never reached. The model does not acquire a matching special case: independent
authored row relations and the shared `LazyVersionModel` already predict the
correct omission.

The source-level guard is one repair location: it returns before recording the
latest provider relation. The reference model and promised checkpoint agree with
the accepted law, and the adapter receives all relevant provider facts before
the failing comparison. Moving the checkpoint or relaxing suffix comparison
would hide this defect.

The bounded grammar reconstructs the two named counterexamples. Removing later
hydration loses resampling; removing cached-object reuse loses the zero-write
support transition; removing the final contraction loses its public consequence;
removing unread rows turns it into exhausted whole-source deletion. Reversed
order and scale preserve the strict-bound distinction. Unsupported orders,
duplicate keys and in-place SDK object mutation are outside the legal grammar.

ORC-011's shared-fault hypothesis is separated by the authored relation model:

this manifest and explicit controlled paths; no actual SDK premise is inferred.
ORC-016 has no ordinary examples embedded in the oracle: both additions use the

would reject a sound repair that writes an equal row to establish core source
authority. The SSR guide's **Initial Data** section explicitly says fresh
adapter sync is authoritative over provisional rows and later hydration cannot
change what the adapter wrote. The support history therefore keeps the actual
cached-object identity premise, permits any sync-write count, and adds a later
public hydration call with a different text value for the newly supported key.
The shared version model is not offered that conflicting value as an allowed
revision. It compares the original provider relation immediately after that
call, then retains the later contraction comparison.

## Accepted baseline versus applied base

The source mutant `public-base-instead-of-accepted` survives the bounded real
persisted peer receiver on both hosts. That receiver deliberately supplies a
finite small prefix while preserving the larger demand's saved rows beyond its
authority. Its restored rows can also be provisional seeds, which permit a
subsequent source insert. This survival does not establish that the mutant is
equivalent, or that the entire portfolio cannot distinguish acceptance from
application.

The same source mutant ran through the unchanged 80-check controlled baseline
instrument: **8 semantic failures / 72 passes**. In each fixed/random campaign,
the held changed answer reports an illegal duplicate insert, the held omitted
answer retains the wrong leading rows, and the held exhausted-empty answer
retains rows after authoritative absence. The generated campaign also rejects
the mutant. These failures follow actual accepted ordinary source writes held
by an optimistic transaction, rather than an inferred hold or a provisional
seed. The empty answer fails the shared public row comparison with an expected
empty relation and actual restored rows. Log
`.review-2377/convex-mutants-final-872-public-base-controlled/public-base-instead-of-accepted-controlled-all.log`,
SHA-256 `39c6db6eb5511d7d56583a47e0523d9f994053d29039d79c32790f80fa005e74`.

The real peer receiver's claim remains finite-prefix preservation across closed
and reopened SDK/storage instances. The controlled lazy oracle supplies the
separate accepted-versus-applied discrimination. An actual exhausted-empty reply
over a held persisted restore has **not** run through the real SDK/storage
receiver, and this portfolio does not claim that receiving cell. A future
witness belongs to the existing Convex lazy and primary persisted-demand oracle
owners. It should preserve source, query and durable observations and record
actual provider deletions independently; an invented snapshot or truncate event
would wrongly prescribe coverage invalidation.

That proposed witness also raises an unexecuted information-sufficiency
hypothesis: an initial larger source can persist a provider lookahead row beyond
the reopened demand's restored window. A later exhausted-empty result may have
to invalidate that durable-only row, which is absent from the Collection's
accepted baseline. No experiment here establishes whether that path fails or
which boundary supplies the needed authority. The coverage map records the
needed witness; the bounded peer result does not settle it.
