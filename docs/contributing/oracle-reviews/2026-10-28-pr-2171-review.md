## Laws, experiments, and inference

The authority for the three policy choices is the maintainer's explicit answers
in this review. Query and Electric discard legacy handler values at runtime.
Inline `getKey` and `schema` bind until query identity changes. Structured source
selections and spreads retain source metadata; a functional selection retains it
only when it returns a source row directly. New functional objects receive the
output Collection's metadata. Colliding reserved names cannot change that rule.
The migration guide and executable owners now state those decisions.

### Handler settlement and refresh

A fulfilled handler must not become a failed transaction merely because it
returned a discarded value. A rejected handler must retain its exact rejection.
The earlier Electric histories did not cross handler verdict with a legacy
return value. The Query owner covered confirmation paths but omitted that
return-value dimension. Those gaps let the adapters disagree at settlement.
The neighboring law is explicit synchronization: completing a Query handler does
not fetch or replace authoritative rows. The handler must await refetch or a
direct write if settlement must expose its confirmed result.

The Electric owner is `electric-oracle.property.test.ts`. Its finite grammar
crosses insert/update/delete, fulfillment/rejection, and absent/legacy returns:
12 histories. Each history holds the handler, checks optimistic rows, then
compares the exact rejection identity, simulated server-write count, and settled
public rows. Successful handlers explicitly deliver ShapeStream confirmation and
await its txid. Each history requires one optimistic and one settled reach.
The driver uses real Collection transactions and controlled SDK event delivery.
It does not claim a live Electric-server result.

The reviewed runtime-rejection wrapper fails three histories at the public
Promise-verdict assertion. The other nine pass. Passing those neighbors rejects
a repair that merely suppresses every handler error. With the rejection wrapper
removed, all 12 pass; the surrounding Electric selection passes 334 runtime tests.

The Query ownership owner crosses CRUD, no confirmation/refetch/direct write,
and absent/legacy return: 18 histories. It checks optimistic rows while held and
exact fetch counts and public rows at settlement. Each history requires both
reach states once. A real QueryClient supplies the fetch boundary. External
focus, reconnect, polling, and invalidation are separate triggers, outside this
grammar. The earlier automatic-refetch calibration failed all nine original
confirmation histories at fetch counts; its evidence remains in
`pr-2171-explicit-query-refresh.md`. The final complete Query runtime suite
passes all 978 tests in 29 files, including both ordered-refetch campaigns.
Moved main tests now initiate refetch explicitly without changing their public
assertions or observation checkpoints.

### Metadata at Collection publication

The earlier metadata owner did not cross selection form, joined source choice,
and individual reserved-name collisions at pending and settled checkpoints.
A source-guessing implementation therefore escaped its narrower comparisons.
The primary virtual-row-fields owner now enumerates 50 legal histories:
single/joined sources, structured projection/spread, functional
projection/spread/direct return, and none/each/all reserved-name collisions.
Direct returns cannot author a collision, so that combination is excluded.
The source's label changes while an optimistic transaction is held. Each history
checks all four fields before mutation, during the hold, and after settlement.
The model decides ownership from the authored selection form, never by comparing
selected values. A clean sibling supplies only the output-generated key.

Declared reach is 25 single-source pending histories, 25 joined-source pending
histories, 40 colliding histories, and two direct functional returns. The minimum
for each declared state is one. Individual `$collectionId` collisions matter:
a fix for only `$key` or all-fields collisions would miss them.

The initial expanded tests failed on the reviewed implementation. The final
50-history grammar, run with the previous compiler restored, fails 26 histories
at metadata assertions and passes 24. This is assertion failure, not setup failure.
The repaired primary and supporting metadata tests pass 57 tests. The broader
metadata/retention selection passes 164. Supplemental tests preserve two spread
orders, an unmatched RIGHT join, direct functional returns, facade projections,
and inline-value shape. The new grammar does not establish every join kind,
arbitrary nested histories, custom-key projections, provider behavior, or every
framework receiving path. Those limits remain explicit in the coverage map.
